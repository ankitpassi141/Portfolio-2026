Tokens, and how to change them

Every color, size and spacing value across the whole site — Home, About, Side Projects, Case Studies, and this page itself — is a CSS custom property in tokens.css. This page renders those same variables, so it stays accurate on its own — edit a token and every page that uses it updates together.

Colour — 6 tokens: 3 surfaces, 3 marks

Ink×41
--ink · #12120F
Text, hairlines, the frame.
Paper×29
--paper · #E7E4DA
Every card surface. The default ground of the whole system.
Paper 2×9
--paper-2 · #D8D4C7
Title bars, the folder canvas — one step off paper, never a third.
Cobalt×15
--cobalt · #2A36E8
Interaction: hover glyphs, drawer row hover, focused status.
Clay×9
--clay · #C9612F
Outcome accent — the 11→4 figure, the IB folder tab, focus rings.
Signal×1
--signal · #7BE86B
The availability dot only. Never type, never a surface.
Rules
— Light only, deliberately — no theme toggle. If dark ever comes back, ink and paper are designed to swap wholesale as a pair. — Cobalt and clay never touch each other and never tint a surface larger than a card body. — Exactly one accent per card. A second accent in the same window means one of them is decoration. — Hairlines are ink at 30% (structure), 18% (rows inside a card), 8% (empty track). No fourth alpha. — Dimmed text is opacity .7 and never lower — that is the contrast floor for a 10.5px label. Text on clay or cobalt takes full-opacity ink or paper instead, since dimming it cannot clear 3:1.

— Archivo 900 only for display numbers and headlines; Archivo 800 only for window titles. Two competing numbers is the most common density mistake in this system. — Display sizes are clamp() so a card can shrink without a second breakpoint. — Any row inside a folder or narrow column sets white-space:nowrap and keeps its label under ~10 characters. Flex children shrink below their text width otherwise, and the value wraps into the label.

06

Changing this globally

Every value on every page — colour, type size, display clamp, spacing step, tracking — is a CSS custom property in tokens.css. style.css, about.css, side-projects.css, pages.css and this page's own design-system.css all read from it; none of them hardcodes a literal. If a component-level file ever needs a value tokens.css doesn't have, the fix is to add a named token there and reference it — not to drop in a raw number. That's the whole point of tokens.css existing separately: one edit, every page that uses it updates. To change a colour everywhere: edit the variable in tokens.css (e.g. --cobalt: #2A36E8;). The site is light-only — there's no theme toggle or dark-mode block to keep in sync. To change the type scale: §03 names every size token — --fs-label, --fs-nav, --fs-body, --fs-body-sheet, --fs-window-title, --fs-dense — plus six display clamps, also named in tokens.css: --display-headline, --display-card, --display-feature, --display-sheet, --display-wordmark, --display-compact. Edit the token, everything using it rescales — nothing sets a size inline anymore. To add a card to the home page: copy an existing .card block in index.html, keep the title bar / body / cap-strip structure, and give it at most one accent colour from §05. Structural knob: --gutter in tokens.css resizes every gap on the grid and frame in one place. If a page needs a value the system doesn't have: don't write a raw number into that page's CSS. Add it to tokens.css as a named, commented token (see --space-tight, --space-7, --space-8, and --display-compact above — all added when About and Side Projects needed something the original four-file audit hadn't covered), then reference it with var(). That keeps this page an accurate map of what's actually in use, instead of drifting out of date.
