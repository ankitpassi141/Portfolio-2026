# Sunflower page

`sunflower.html` + `css/sunflower.css` + `js/sunflower.js`, linked from the Experiments page
(`js/experiments-data.js`). A procedural Three.js (r170, ES modules via import map from jsDelivr, no build step)
sunflower in a meadow that follows the real sun. Started from the standalone `sunflower-sun-tracker` project.

## What it does
- **Sun:** `sunPos()` (SunCalc-style maths) turns the viewer's GPS position + clock into azimuth / altitude. That one
  vector drives the shadow-casting `DirectionalLight`, the sky, the stars and where the flower's face points.
- **Sky:** three's physically based `Sky` is rendered into a cube map every time the sun has moved > 0.35° (max every
  250 ms). That cube map is both the backdrop and (through PMREM) the image-based light, so sky, ambient light and sun
  can never disagree. Stars fade in below −3° altitude.
- **Location + compass:** location is requested on load (Delhi if blocked). iOS `webkitCompassHeading` needs a tap, so the first touch on the scene asks for motion permission;
  Android `deviceorientationabsolute`. Heading steers the camera yaw; the phone's tilt steers pitch, so you can tip the
  phone up to find the sun in the sky. Drag also works: with a compass it springs back after ~350 ms, without one it sticks.
- **Day / night:** heliotropism by day; as the sun drops below the horizon the neck arcs over, the head hangs, petals
  fold and leaves sag (`droop = smooth(0, −8, alt)`, eased in real time). Night keeps a brightness floor.
- **UI:** top-right shows only the local time and place; bottom-left is a reset button (zoom, look offset). Pinch or scroll to zoom. `?t=HH:MM` pins the page to that local time (screenshots, sharing).
- **Translucency:** petals, leaves and grass glow when the sun is behind them as seen from the camera
  (`addTranslucency()` — an emissive term injected with `onBeforeCompile`).

## Conventions (easy to break)
- World axes: **+X east, +Y up, −Z north**. Azimuth is degrees clockwise from north; camera heading uses the same
  convention. The camera stands `dist` metres from the plant and looks along `heading`/pitch.
- The head's normal is local **+Z**. The flower faces the sun, so **looking toward the sun shows the flower's back** —
  that is correct. The first view starts at `sun az + 210°` so visitors see the face.
- `buildStem(phi)` rebuilds a 160×14 tube; only call it when `|phi − stemPhi| > 0.004`.
- Only `sunLight` casts shadows. Grass casts shadows within 2.6 m only (and not at all on touch screens).
- Touch screens (`(pointer: coarse)`) get a smaller meadow (R 5 m vs 8 m), 1k shadow map and 256² sky cube.

## Assets
Ground: Poly Haven `aerial_grass_rock` (1k diffuse / roughness / GL normal, CC0) in `images/sunflower/`, licence note in
`images/sunflower/LICENSE.txt`. Two differently scaled samples are blended in the shader so the 800× tiling never shows.
Everything else (flower, leaves, grass, textures) is generated in code.

## Known limits
- Compass sign / offset and real-device frame rate are untested (only desktop Chromium was checked).
- Procedural flower: good real-time realism, not photographic. A scanned glTF flower (`GLTFLoader`) is the obvious upgrade.
- Reverse geocoding for the place name uses `api.bigdatacloud.net` (keyless, client-side); failure just shows "Your location".
- Compass needs HTTPS (the live site is; `localhost` also counts on desktop).

## Rendering
No post-processing: the scene renders straight to the screen with ACES tone mapping (exposure follows the sun, see `toneMappingExposure` in the frame loop). The earlier bloom / grain / lifted-blacks film pass was removed because it made the scene look hazy.

## Sound, fireflies, meadow LOD
- `js/sunflower-audio.js`: Web Audio synthesis, no files. Day = breeze + birdsong; night = quieter breeze + crickets + an owl;
  `update(day)` crossfades. On by default but starts at the first touch/click (autoplay rules); the speaker button
  (bottom-right) toggles it and the choice is kept in `localStorage` (`sunflower-sound`).
- Fireflies: `THREE.Points` + shader (wander + blink), 170 (90 on touch), visible when sun altitude < ~4° (`fireflyU.uAmt`).
- Meadow: LOD0 blades 0–8 m, LOD1 tufts 8–35 m, LOD2 flat tufts 35–130 m; beyond that fog + ground texture. Each ring is
  split into 6/12/16 angular sectors, each an `InstancedMesh` with a bounding sphere, so off-screen sectors are culled.

## Free assets used (all licences in `images/sunflower/LICENSE.txt`, `audio/sunflower/LICENSE.txt`)
- **Disc + petals:** crops of a public-domain macro photo of a sunflower head (George Chernilevsky, Wikimedia Commons) —
  `sunflower_disc.webp` (circular alpha, also used as the bump map) and `sunflower_petal.jpg`. They replace the procedural
  canvas textures once loaded; the procedural ones remain as the instant fallback. No CC0 sunflower *mesh* was found
  (Poly Haven has none; Sketchfab needs a login to download), so the geometry is still generated in code.
- **Ground:** Poly Haven `sparse_grass` (CC0).
- **Grass clumps:** Poly Haven `grass_medium_02` glTF (CC0), two lightest variants, 4.5–22 m, 12 sectors each, alpha-tested.
- **Sound:** three BigSoundBank CC0 field recordings cut into 70 s loops with ffmpeg (`day-breeze`, `day-birds`, `night-crickets`),
  decoded with Web Audio and crossfaded by `day`. Levels are set in `GAIN` in `js/sunflower-audio.js`.

## Location fallback
GPS (live) → IP lookup (`ipwho.is`, accepted only if its longitude agrees with the device clock's UTC offset within 35°, so VPNs are
ignored) → the timezone's city / region. The place label says "(approx.)" until GPS arrives.

## Moon mode (Sun / Moon switch)
- **Switch:** bottom-centre `Sun | Moon`. First visit starts on the moon after dark (sun altitude < −3°), otherwise the sun; a manual choice is
  remembered in `localStorage` (`sunflower-mode`). `?mode=moon|sun` overrides.
- **Astronomy:** `js/sunflower-astro.js` — `moonPos` (az/alt, ~0.3°), `moonPhase` (fraction lit + phase), `nextMoonEvent` (rise/set, 10-minute scan + bisection).
  Same low-precision series as SunCalc (BSD-2). Checked against known events: full moon 2026-10-26 reads 99.8 % lit, new moon 2026-11-09 0.7 %.
- **Moon in the sky (both modes):** a sphere with NASA's LROC map (`images/moon/`, public domain), lit only from the real sun direction so the bright limb is
  always right; its north pole is aimed at the celestial pole. Apparent size is exaggerated to ~2° (real: 0.5°) so it reads on screen. A halo sprite and a
  cool `moonLight` (own shadows, strength ∝ phase × altitude, only when the sun is down) light the meadow; the sun light is hidden when ~0 so only one
  shadow map renders at a time.
- **Brahma Kamalam:** the *Epiphyllum oxypetalum* ("Queen of the Night") that Telugu/Tamil speakers call Brahma Kamalam, not the Himalayan *Saussurea obvallata*.
  No free 3D model exists, so it is generated in code (`makeBloom`, `stemGeometry`): scalloped flat stems, a sagging tube, 30 narrow pinkish outer tepals,
  four rings of broad white petals, 150 stamens and a star-tipped style. Procedural vein textures (a CC0 photo set of the real flower is on Wikimedia Commons
  if you want to swap in photo textures). `bloom` eases to `smooth(0, −8, sun alt) × smooth(−1, 6, moon alt)`: it opens after dark once the moon is up, turns
  to face it, and hangs as a closed bud otherwise (the panel then shows the next moonrise).
- **Panel in moon mode:** phase name + % lit, and "Up now · N° high · sets HH:MM" or "Below the horizon · rises HH:MM".

## three.js version
Importmap in `sunflower.html` pins `three@0.187.0` (jsDelivr). The only changes needed from 0.170: `PCFShadowMap` (soft shadows are built in now) — and the
Sky add-on now draws procedural clouds. Other pages on the site still use their own, older three.js builds and were not touched.
