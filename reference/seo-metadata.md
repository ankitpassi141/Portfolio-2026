# SEO / Social Metadata — Reference

Every page has a unique `<title>` + `<meta name="description">`, plus a
full set of Open Graph and Twitter Card tags, so links to this site render
a proper preview card on Twitter/X, LinkedIn, Slack, Discord, iMessage,
etc.

## To edit a page's SEO title/description/image

Edit [seo-data.json](../seo-data.json), then run
**`scripts/sync-seo-meta.ps1`** (or double-click
`scripts/update-seo.bat`). That's the only place og:/twitter: content
comes from — Twitter's tags are generated from the exact same
title/description/image as Open Graph's, so you only ever type them once.

```json
{
  "path": "study/smartadc.html",
  "title": "SmartADC — Ankit Passi",
  "description": "Redesigning a virtual Assessment & Development Center workflow...",
  "type": "article",
  "image": "images/smartadc/og.jpg"
}
```

- `type` — `og:type`. Use `"website"` for most pages, `"article"` for the
  case studies.
- `image` — **optional**. Leave it out and the page falls back to
  `site.defaultImage` (the wordmark card at
  [images/og-default.jpg](../images/og-default.jpg)). Set it to use a
  custom image for that one page instead, like the three case studies do
  with their own hero shots.
- Image dimensions: 1200×630 (the standard OG size) is what every image
  currently in use is cropped to — keep new ones at that ratio so they
  don't get awkwardly cropped by whichever platform renders them.
- Format: JPG or PNG only. WebP has inconsistent support across social
  crawlers (Twitter/X in particular) — if a source image is `.webp`,
  convert a copy first (`ffmpeg -i src.webp -vf "scale=1200:630:force_original_aspect_ratio=increase,crop=1200:630" out.jpg`).

## Why a separate file, and why a script

Social crawlers (Twitter/X, Facebook, LinkedIn, Slack, Discord...) read
**raw HTML only** — they don't run JavaScript. So unlike most of this
site's per-page text (which lives in a `*-data.js` file and gets rendered
into the DOM at runtime), these tags have to already be static text in
each page's HTML source before any script runs.

[scripts/sync-seo-meta.ps1](../scripts/sync-seo-meta.ps1) writes a single
clearly-marked block into each page's `<head>`:

```html
<!-- SEO:START (generated by scripts/sync-seo-meta.ps1 from seo-data.json - do not hand-edit this block) -->
...og: and twitter: tags...
<!-- SEO:END -->
```

Re-running the script finds and replaces that exact block, so it's safe
to run as many times as you want.

**It deliberately does NOT touch each page's own `<title>` /
`<meta name="description">` tags above that block.** A few of those carry
an `id` (`<title id="aboutPageTitle">`, `<meta name="description"
id="pbPageDescription">`) that the page's own JS updates at runtime from
its `*-data.js` file — see about.js, experiments.js, and the three
case-study renderers (smartadc.js, automated-test.js, power-bi.js).
Rewriting those tags here would either strip that `id` and silently break
that JS, or risk seo-data.json's copy drifting from the `*-data.js` file
that actually owns that page's on-screen copy.

**The practical upshot**: for those five pages (About, Experiments,
SmartADC, Assessment Generator, Power-BI), there are two related but
separate places with a title/description —

| | Owns | Read by |
|---|---|---|
| `js/about-data.js` (etc.) `pageTitle`/`pageDescription` | the on-screen/tab title, set via JS after load | browsers, after JS runs |
| `seo-data.json`'s matching entry | the static `<title>`/description already in the HTML, and the og:/twitter: block | crawlers, and browsers before JS runs |

They should say the same thing (and do today) — if you change one, change
the other to match, then re-run the sync script. For every other page
(no `*-data.js` file, title only ever lived as a plain static tag), there's
only seo-data.json to edit.

## The default image

[images/og-default.jpg](../images/og-default.jpg) — a 1200×630 wordmark
card in the site's own ink/paper/cobalt palette. Generated with .NET's
`System.Drawing` (no external tool needed) rather than a real design
program; swap the file for a proper designed version whenever you want
one, same filename, no other changes needed.

## Page-by-page status

| Page | og:type | Image |
|---|---|---|
| Home, About, Case Studies, Side Projects, Experiments, Gaming & Exploration, Photo Gallery, Design System, Case Study (template) | website | default |
| SmartADC, Assessment Generator, Power-BI Tool | article | own hero shot |

The three `/raw` case-study pages (private, `noindex, nofollow`) are
intentionally **not** in seo-data.json — they already say "not for
sharing" on the page itself, so a social preview card for them would run
against that intent. Their existing `<title>`/description tags are
untouched and still fine as page titles for anyone who does have the
direct link open.
